# 원격 접속 — 보류 (조사 결과 요약)

원격 데스크톱(`mstsc`) 없이 브라우저로 대시보드를 여는 기능은 **현재 보류**한다.
지금은 기존처럼 **mstsc(원격 데스크톱)** 로 접속해 사용하고, 프로그램이 충분히 안정화됐다고
판단되면 그때 다시 검토한다. (재검토 시 아래 조사 결과부터 보면 됨)

## 환경 제약
- 클라우드PC: **Windows Server 2012 R2 64bit (EOL, OS 업그레이드 불가)**.
- **NAT 뒤(사설 IP)** — 본인이 직접 포트를 못 열고, 제공업체(몽클라우드) 포트포워딩이 필요.
  업체 문의 없이 자력 해결하려면 아웃바운드 터널이 필요.

## 검토한 방법과 결론
| 방법 | 결과 |
|---|---|
| 제공업체 포트포워딩 요청 | 가능하나 이메일 문의 필요 → 사용자가 원치 않음 |
| Tailscale / 최신 ZeroTier | Server 2016+/구버전 강제 → **설치 불가** |
| 최신 cloudflared | Go 1.21이 Server 2012 지원 종료 → **실행 불가**(구버전만, 취약) |
| playit.gg 무료(Minecraft 타입) | 에이전트는 실행됐으나 **웹 HTTP 미작동**(MC 핸드셰이크 기반 라우팅) |
| playit.gg 유료 전용TCP / Pinggy Pro | 동작하나 **예산 초과**(연 ₩4만+), 예산은 ~₩2만 |
| plink(PuTTY) + serveo/localhost.run | 2012 R2 실행 보장·무료지만 **제3자 릴레이가 트래픽(비밀번호) 복호화 가능** → 보안상 보류 |
| 싼 도메인 + serveo 커스텀도메인 | 예산 내 가능하나 위 보안 우려 동일 |

## 결론
- 현재는 **mstsc 유지**. 모든 무료/저가 터널은 제3자가 트래픽을 보거나 EOL OS에서 불안정.
- 재검토 시 후보: (a) 프로그램 안정화 후 playit 유료/Pinggy 등 소액 턴키, (b) 본인 도메인 + 신뢰 가능한 터널.

## 참고: 이미 적용된 보안 코드
- `web/auth.py`: 로그인 무차별 대입 방어(IP별 15분 내 5회 실패 → 10분 잠금)는 이미 반영됨
  (원격 노출 대비용이지만 로컬에서도 무해). 상수 `_LOGIN_MAX_FAILS/_LOGIN_WINDOW/_LOGIN_LOCK`.
- 노출 시 권장: 강한 `WEB_PASSWORD`/`WEB_SECRET_KEY`(.env), Bithumb API 키 거래전용(출금 비활성).
