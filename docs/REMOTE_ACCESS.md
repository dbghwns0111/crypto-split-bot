# 원격 접속 가이드 — 브라우저로 웹 대시보드 열기

원격 데스크톱(`mstsc`) 없이 **로컬PC·노트북·스마트폰 브라우저**에서 웹 대시보드를
URL로 직접 여는 방법입니다.

## 환경 전제
- 클라우드PC: **Windows Server 2012 R2 64bit (EOL)** — OS 업그레이드 불가.
- RDP가 `주소:포트` 형태로 접속됨 → **인바운드 포트 개방이 가능한 네트워크 경로 존재**.
- 앱은 이미 `0.0.0.0:5000`에 바인딩되고, 세션 비밀번호 로그인 + IP 화이트리스트를 갖춤.

> Tailscale(Server 2016+)·최신 ZeroTier·최신 cloudflared는 EOL OS에 설치 불가하므로,
> **클라우드PC에 아무것도 새로 설치하지 않고 포트만 개방**하는 방식을 사용한다.

---

## 1. 포트 5000 개방 (클라우드PC에서 1회, mstsc로 접속해 수행)

### 1-1. Windows 방화벽 인바운드 허용
관리자 권한 명령 프롬프트(또는 PowerShell)에서:
```
netsh advfirewall firewall add rule name="CryptoSplit Web" dir=in action=allow protocol=TCP localport=5000
```
삭제하려면:
```
netsh advfirewall firewall delete rule name="CryptoSplit Web"
```

### 1-2. 제공업체 방화벽 / 포트포워딩
RDP 포트를 열었던 곳(클라우드 콘솔의 보안그룹 / 포트 매핑 / 방화벽)과 **동일한 위치**에서
TCP 5000(또는 외부포트 → 내부 5000 매핑)을 허용한다.
- RDP가 `주소:포트`로 동작 중이라면 같은 경로로 5000도 열 수 있다.

### 1-3. 앱이 떠 있는지 확인 (클라우드PC에서)
```
curl http://localhost:5000/login
```
정상이면 로그인 페이지 HTML이 반환된다.

---

## 2. 보안값 설정 (`.env`) — 인터넷 노출이므로 필수

클라우드PC의 프로젝트 루트 `.env`에 아래를 설정한다. (`.env`는 git에 올라가지 않음)
```
# 대시보드 로그인 비밀번호 — 반드시 길고 추측 어렵게 (인터넷 공개 로그인)
WEB_PASSWORD=여기에_강력한_비밀번호

# 세션 서명 키 — 설정 시 봇 재시작 후에도 로그인 유지 (32바이트 hex 권장)
WEB_SECRET_KEY=여기에_랜덤_32바이트_hex
```
`WEB_SECRET_KEY` 생성 예 (아무 PC의 파이썬에서):
```
python -c "import os;print(os.urandom(32).hex())"
```

> 설정 후 봇(main.py) 재시작 또는 설정 탭에서 비밀번호 저장 시 즉시 반영된다.
> `WEB_PASSWORD`가 비어 있으면 인증이 **비활성**(누구나 접속)되므로 반드시 채울 것.

---

## 3. 접속하기 (로컬PC / 노트북 / 폰)

브라우저에서:
```
http://[RDP에 쓰는 것과 동일한 주소]:5000
```
- 로그인 페이지에서 `WEB_PASSWORD`로 로그인.
- 폰은 Wi-Fi/LTE/5G 어느 망에서도 접속 가능(공인 주소이므로).

---

## 4. 로그인 무차별 대입 방어 (자동 동작)

`web/auth.py`에 IP별 로그인 시도 제한이 내장되어 있다(추가 설정 불필요):
- 한 IP에서 **15분 내 5회 연속 실패** → 그 IP를 **10분간 잠금**(비밀번호 검사 없이 차단, HTTP 429).
- 올바른 비밀번호로 **로그인 성공 시 해당 IP 기록 초기화**.
- 클라우드PC 자신(127.0.0.1 등 로컬)은 잠금 예외(자기 잠금 방지).

정책 값은 `web/auth.py` 상단 상수에서 조정 가능:
`_LOGIN_MAX_FAILS`, `_LOGIN_WINDOW`, `_LOGIN_LOCK`.

## 5. (선택) 추가 하드닝 — 필요 시에만

### 5-1. 비표준 포트로 운영
자동 포트 스캐너 노이즈를 줄이려면 5000 대신 임의 포트 사용:
```
python main.py --port 48217
```
또는 `config/settings.yaml`의 `web.port` 변경. (방화벽/포워딩도 해당 포트로 맞출 것)

### 5-2. HTTPS(자체 서명 인증서)
평문 전송이 꺼려지면 자체 서명 인증서로 HTTPS 구동 가능(브라우저 경고 + 모바일 신뢰 설정 번거로움).
Server 2012 R2 PowerShell의 `New-SelfSignedCertificate`로 인증서를 만들고
`app.run(..., ssl_context=(cert, key))` 형태로 구동한다.
> 강력한 `WEB_PASSWORD`를 쓴다면 개인용으로는 평문(HTTP)도 실무상 무방.

---

## 6. 보안 메모 — 실제 위험 지점

포트 5000 개방은 `.env`나 API 키/비밀번호를 **노출하지 않는다**:
- `.env`는 git 제외(`.gitignore`)이고, 웹서버는 `.env`를 서빙하지 않음(정적폴더는 `web/static`만,
  이미지 라우트는 경로 탈출 차단).
- `GET /api/settings`는 API 키를 마스킹하고 웹 비밀번호는 값이 아닌 설정 여부만 반환.
- 따라서 `.env`는 사실상 RDP로 머신에 접근해야만 읽을 수 있다.

대신 신경 써야 할 곳:
- **RDP**: 인터넷 노출 + EOL OS(보안 패치 없음) → 최우선 표적. RDP 비밀번호를 강하게,
  가능하면 제공업체 방화벽에서 RDP 접속 IP를 제한하고 계정 잠금/NLA를 켤 것.
- **Bithumb API 키**: 가능하면 **거래 전용(출금 비활성)** + API 허용 IP를 클라우드PC IP로 제한.
  → 만에 하나 `.env`가 유출돼도 자금 이탈 위험을 최소화.
- **대시보드 비밀번호**: 봇 제어(시작/중지·설정변경) 권한이므로 강력하게 유지.
